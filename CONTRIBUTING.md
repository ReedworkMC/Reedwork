# Contributing to Reedwork

Thank you for your interest in contributing to Reedwork! ❤️

Reedwork is an open-source framework designed to make PaperMC plugin
development simpler and reduce boilerplate.

Contributions of all kinds are welcome, including bug reports, feature
requests, documentation improvements, and code contributions.

## Getting Started

1. Fork the repository.
2. Clone your fork locally.
3. Create a new branch for your changes.
4. Make your changes.
5. Make sure the project builds successfully.
6. Run the relevant tests.
7. Open a pull request.

Please keep pull requests focused on a single change whenever possible.

## Reporting Bugs

Before opening a bug report, please check whether the issue has already
been reported.

A useful bug report should include:

- a clear description of the problem;
- steps to reproduce it;
- the Reedwork version;
- the PaperMC version;
- the Minecraft version;
- relevant error messages or stack traces;
- a minimal example when possible.

## Feature Requests

Feature requests are welcome.

Please explain:

- what problem the feature would solve;
- how you would expect the feature to work;
- why the feature would be useful to Reedwork users.

For larger changes, opening an issue before implementing the feature is
recommended so the approach can be discussed first.

## Pull Requests

Before submitting a pull request, please make sure that:

- the project builds successfully;
- existing tests pass;
- new functionality includes appropriate tests where applicable;
- public APIs are documented where appropriate;
- documentation is updated when necessary;
- the changes are focused and do not contain unrelated modifications.

Please use a clear and descriptive pull request title.

## Code Style

Please follow the existing code style and conventions used throughout
the project.

Avoid introducing unnecessary dependencies or abstractions.

When modifying public APIs, consider backwards compatibility and the
impact on existing Reedwork users.

## Commit Messages

Please use clear and descriptive commit messages.

For example:

    Fix command registration with multiple arguments

instead of:

    fix stuff

There is currently no strict commit message format required.

## Discussions and Questions

If you are unsure whether an idea or change belongs in Reedwork, feel free
to open an issue or start a discussion before implementing it.

We would rather discuss a larger change early than review a large pull
request that takes Reedwork in an unexpected direction.
